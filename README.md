「Parblo Intangbo M」绘图板的Windows用户态驱动程序（非官方版本），通过HID API访问设备、经Windows Ink注入笔事件，并提供图形界面。

本程序是[Linux版本](https://github.com/dfxyz/parblo-intangbo-m-driver)的移植，但两边的实现方式不同，因此没有共用代码。

提供下列功能：
- 支持自定义按键映射（包括画笔上的两个侧键），可配置多套方案并随时切换
- 支持修正设备声明量程与真实感应范围之间的偏差，并按显示器比例映射
- 支持自定义压感响应曲线
- 常驻托盘，界面提供原始数据监视与日志

# 使用方法

## 构建
```
cargo build --release
```

产物为单个可执行文件，无需安装驱动、无需管理员权限。默认读取与可执行文件同目录、同主文件名的配置文件，例如`parblo.exe`对应`parblo.toml`；也可以用命令行参数指定配置文件路径。

配置文件可参考`config.example.toml`。若配置文件不存在或解析失败，程序会以空配置启动（不映射任何按键），随后可直接在界面里配置并保存。

## 界面
| 页面 | 用途 |
| --- | --- |
| 按键映射 | 配置各按键的映射；「录制」可直接按下想要的组合来填写 |
| 映射区域 | 修正可感应范围，详见后文「映射区域」 |
| 压感曲线 | 调整笔压的响应曲线 |
| 原始数据 | 实时查看设备上报的坐标、压力、倾斜与按键 |
| 日志 | 查看握手、连接、断开重连等记录 |

启动时只显示托盘图标，双击图标或从托盘菜单选择「显示窗口」即可打开界面。关闭窗口只会隐藏到托盘，驱动仍在运行；从托盘菜单选择「退出」才会真正结束。程序运行期间再次启动会唤回已有窗口，不会出现第二个实例。

设置环境变量`PARBLO_DEBUG`可输出更详细的日志。

# 配置说明

配置文件使用TOML格式，界面上的改动都能保存回该文件。

## 按键映射
`keymap`是一个数组，每个元素对应一套按键方案；`keymapIndex`记录上次使用的方案下标。

每套方案中可配置下列字段：
- `button0`~`button7`：绘图板上左侧从上到下的八个按键
- `ring0`、`ring1`：转环逆时针、顺时针旋转
- `ringButton`：转环中间的按钮
- `stylusButton0`、`stylusButton1`：画笔上的下侧键、上侧键

每个字段可以配置为：
- 单个按键，或用`ctrl`、`shift`、`alt`、`meta`组合而成的快捷键
    ```
    a~z 0-9 - = \ ` [ ] ; ' , . /
    esc tab backspace enter space
    home end pageup pagedown insert delete
    f1~f12 up down left right
    num0~num9 numplus numminus nummultiply numdivide numdot
    ```
- 鼠标按键：`mouseLeft`、`mouseMiddle`、`mouseRight`
- 特殊行为：
    - `switchSchema`：切换到下一套方案
    - `fallback`：沿用前一套方案的映射；第一套方案中等同于`none`
    - `none`：禁用该按键

若某个字段未配置，默认使用`fallback`。

## 映射区域
`area`用于描述绘图板上参与映射的区域，取值归一化到设备声明的量程：
- `xMin`、`xMax`、`yMin`、`yMax`：区域的四条边界
- `anchor`：按显示器比例修正时的基准角，可取`topLeft`、`topRight`、`bottomLeft`、`bottomRight`

设备声明的坐标量程通常大于真正能感应到的范围（本机实测X轴只能到声明值的90.8%），直接按声明量程映射会导致笔尖走不到屏幕边缘。在「映射区域」页把笔贴着板子边缘划一圈，程序会记录实际到达过的坐标极值，点击「用观测极值填充区域」即可写入。

区域确定后，程序会在其中取一块符合显示器长宽比的矩形映射到全屏，并靠向`anchor`指定的角，因此笔迹不会因为板子与屏幕比例不一致而变形。

## 压感曲线
`pressure.points`是一组控制点，横轴为设备上报的原始压力，纵轴为注入系统的压力，两者都归一化到`[0, 1]`，点之间按线性插值。

控制点可以自由拖动，首尾之外的区间按常数外推，因此：
- 把首点右移即可忽略过轻的压力
- 把末点左移即可提前到达满压

# 已知问题
- **压感精度被压缩**：设备提供8192级压感，而Windows Ink的合成笔上限为1024级，注入时必须压缩。这是该接口的固有限制，即使接入真实的数位笔也是同样的精度。
- **程序退出后绘图板会失灵**：握手后设备就不再使用标准HID接口，而恢复默认模式的命令没有逆向出来，因此程序退出后绘图板不再上报任何事件。重新运行本程序即可恢复，不必拔插设备。
- **进程被强制结束时可能残留按键状态**：注入出去的按键由本程序负责释放，正常退出、设备断开、驱动线程异常等路径都已覆盖，但进程被强制结束时来不及处理。此时手动按一下对应的物理按键即可解除。
- **笔侧键不使用Windows Ink的第二按钮语义**：系统的「将笔按钮用作右键单击等效项」会拦截该状态自行判定右键手势，导致应用收不到即时的按钮状态，因此侧键统一走按键映射通道。
- **标准HID接口在Windows下无法直接读取**：鼠标与键盘集合会被系统拒绝访问，数位板集合会被笔输入栈独占，因此只能使用厂商私有接口，这也是官方驱动的做法。
